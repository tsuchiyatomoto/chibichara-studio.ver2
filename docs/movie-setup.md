# Movieの起動と検証

MovieはNext.jsと別のPythonサービスで動く。初期構成はWindowsの単一PC、ローカルディスク、RTX 3080 10GB。文字起こし・日本語alignmentはCPUで動かし、既存IrodoriのPython環境を変更しない。

入力は最大60分のMP4。ゲーム音と実況音声に独立した2本以上の音声トラックが必要。

## 起動

1. Python 3.12、FFmpeg、ffprobeを用意する。
2. `npm run movie:setup` で `.movie-venv` に固定した依存関係をインストールする。
3. `.env.local` にVertex AIの既存認証設定と `GEMINI_AUDIO_MODEL` を設定する。モデルは実際のプロジェクトで利用可能な音声入力・JSON出力対応モデルを指定する。
4. Irodoriサーバーへ下記の小さな拡張を適用し、再起動する。
5. `npm run movie:start`、`npm run dev` をそれぞれ起動し、`http://localhost:3000/movie` を開く。

初回の解析ではfaster-whisper large-v3と日本語CTCモデルを取得するため、時間と数GBのディスク容量が必要。Movieを閉じても処理は継続するが、PCやサービスの停止中は処理できない。サービス再起動時に未完了工程を再開する。

文字起こしでは「あー、えー、えっと、そのー、あのー、うーん」を認識ヒントとして各処理窓に渡し、フィラーも台詞に残すよう促す。用語辞書は引き続きinitial_promptに渡す。これは認識を誘導する設定であり、フィラーの完全な認識や誤挿入の防止を保証するものではない。認識した本文はそのまま読み上げ用の文章に引き継ぐ。保存済みの文字起こしは変更しないため、設定の適用にはMovieワーカーを再起動し、新しいジョブで解析する。

## Irodori拡張

対象は既存の所有者別資産APIを含むサーバーのローカルrevision `3316cef87c11f2f5b2b805f9bf603d6440bf758e`。公式リポジトリだけでは既存のVoice拡張が不足するため、このrevisionを含むサーバーを別途保存・配布する必要がある。

`irodori-movie-snapshot.patch` はこのrevisionからの差分。サーバーのルートで次を実行する。

```powershell
git apply --check C:/dev/chibichara-studio.ver2/docs/irodori-movie-snapshot.patch
git apply C:/dev/chibichara-studio.ver2/docs/irodori-movie-snapshot.patch
```

既に適用済みなら再適用しない。追加APIは `GET /v1/audio/voice-assets/{id}/content`。既存と同じ認証・所有者検査を行い、資産ストアのロック内でモデルのバイト列を取得する。声の置換・期限削除と競合して読み取り途中のファイルが消えることを防ぐ。

Movieは取得したモデルをジョブ専用ディレクトリへ保存し、サーバーにその `ref_embed` パスを送る。したがって現バージョンではTTSとMovieが同じファイルシステムを参照する必要がある。遠隔TTS・サーバーレス環境にはそのまま配置できない。VoiceのUIと新規生成リクエストは変更しない。

## 保存と認証

- 非公開 `.movie-data` にSQLite WAL、動画、音声、モデルスナップショットを保存する。Gitには含めない。
- Next.jsの既存所有者cookieを使う。Movieサービスはループバックで待ち受け、Next.jsが秘密トークンと所有者を付与する。ブラウザからサービスへ直接アクセスさせない。
- `MOVIE_DATA_DIR` を変更する場合は両サービスで同じ絶対パスを指定する。トークンはその中の `service.token` を共用するか、同じ `MOVIE_WORKER_TOKEN` を設定する。
- OSのファイルロックでワーカーの重複起動を防ぐ。uvicornのworkersは1。ロックが取得できない場合は起動しない。
- 動画は8MiBチャンクで送信。位置とhashを照合し再送を重複保存しない。公開ダウンロードは所有者検査とRangeに対応する。
- 完了・中止・失敗・アップロード待ち・確認待ちのファイルは最終更新から24時間で削除する。実行中は削除しない。学習済み声モデル本体は削除しない。

## 音声解析エラーの確認

Movie画面で動画を選び、「音声解析の診断ログ」を開くと、Geminiへの各リクエストの失敗区間・所要時間・試行回数・120秒の設定期限・モデル・エラー詳細を確認できる。「失敗したリクエストだけ表示」を解除すると、成功した試行や開始後に応答が未記録の試行も表示する。再試行で成功しても途中の失敗は消えない。画面は直近100試行まで表示し、「診断ログをダウンロード」から全記録を取得できる。

ログはジョブのディレクトリの `audio-analysis.jsonl` に追記する。対象区間と、前後の無音を除いた送信音声の区間を別々に記録する。所要時間はAPI呼び出し単位で、再試行前の待機時間は含めない。Googleのエラーコード・本文・利用可能なリクエストID等も保存する。音声本体・台詞・プロンプト・認証ヘッダーは送信ログに含めない。失敗した試行は `event: "audio_analysis_request"` としてワーカーの標準エラーにも出力し、`npm run movie:background` 使用時は `logs/movie/*.err.log` で確認できる。

ログの対象は音声イベント解析と発言の再確認で、成功の表示はAPIが応答したことを示す。回答内容の検証結果や生成音声の品質判定とは別。ログには既存のジョブと同じ所有者制限・保存期限を適用する。Movieワーカーを再起動した後の新しいAPI呼び出しから記録され、機能追加前の失敗の詳細やキャッシュ利用だけで完了する区間は記録されない。

```powershell

```

Movieテストは実FFmpegを使用する。AIサービスの代わりに固定応答を使う統合テストと、アップロード再開、所有者境界、発言境界、編集競合、時間補正、元実況が混ざらない出力、Range取得、中止、永続保存を含む。実際の感情再現度・機械的ノイズの有無は別途試聴が必要。

60分のメディア検証は `$env:MOVIE_LONG_TEST='1'; npm run movie:test` で有効になる。UIテストはNext.jsとMovieを起動した状態で `npx playwright test tests/movie-ui.spec.ts --workers=1` を実行する（初回は `npx playwright install chromium`）。

2026-09-15の確認結果：通常のMovieテスト15件、Irodori回帰73件、ブラウザ操作1件が成功。別実行の30分検証用MP4も成功し、出力の長さ・映像フレーム数を確認した。既存の約5.6秒の合成音声から実ASR・日本語alignment・Gemini解析・保存モデルでのIrodori生成まで動作し、生成後の読みを再解析して一致を確認した。実実況30分全体の生成と、人による感情・音質評価はこの検証には含めていない。

台詞は最初のWhisper文字起こし（編集した場合は保存した読み）を使って生成する。生成後の再文字起こし・読みの比較・不一致による自動再生成は行わない。旧仕様の読み不一致だけで止まった発言は、続行時に保存済み音声の形式・長さ・発声の有無を確認して再利用し、ファイルが使えない場合のみ生成する。感情と話し方に加え、解析した話速と原文内の強調箇所をcaptionへ反映する。

## 現在の制約

### 台詞と非言語発声の区間解析

Whisperの文字起こしは仮の台詞として保存し、Geminiへの音声入力から台詞・笑い声などの時刻と種類を別に求める。推定時刻をVADと照合し、説明されない音は該当区間だけを未解決候補として追加する。発声時刻がVADと一致しない場合も、そのイベントだけに警告を付ける。周囲の正常な台詞・感情・発声種類は保持する。未判定部分がある場合や回答自体が不正な場合は、Whisper発言の内部を避けた無音の切れ目で短く分割し、長い前後の無音も除いて再試行する。片側だけ成功した場合も成功した結果を保持し、再試行で解決しなかった箇所には前の回答で正常だったイベントを復元する。音声を処理できないという回答は正常な判定として保存せず、解析終了時に該当発言を無音化する。

Vertex AIが504 `DEADLINE_EXCEEDED`を返した場合は、同じ音声をそのまま3回送り直さない。ASR発言を切らない別境界または異なる前後文脈で局所的に再試行し、それでも失敗した区間の発言だけを無音化して後続区間の解析を続ける。各窓の成功結果は内容アドレス付きキャッシュへ保存するため、別窓の失敗で破棄しない。

未判定区間の中に完全に収まるWhisperの台詞は、その区間だけの仮台詞として保持する。正常なイベントをまたぐ文章の全文を未判定部分へコピーしない。対応する文字を特定できない部分は空の台詞で記録し、解析終了時に無音化する。元の文字起こしは`transcript.json`に残す。

最終的な台詞本文と基本区間はWhisperの発言を正解として扱う。Geminiが返す複数の短い台詞イベントは、重なるWhisper発言へまとめ、Geminiの語句で本文を置き換えない。Geminiの台詞本文との比較や不一致警告は行わない。Geminiは区間、感情、話し方、笑い声などの分類だけに使う。Whisper発言に対応しないGeminiの台詞イベントは破棄する。発言の後ろに独立して続く笑い声・咳・息などは、文章の終端から切り出して残す。

リップノイズは音声解析で発声とは別に判定し、発言データ・合成対象から除外する。文字も発声種類も特定できない0.5秒未満の音は未判定発声として追加しない。短い台詞・相槌や、笑い・咳など種類を判定できた発声は保持する。長い未判定音は理由を記録して無音化する。変更前の解析キャッシュは再利用しないが、保存済みジョブの一覧は自動で書き換えない。適用にはMovieワーカーを再起動し、動画を新しいジョブとして解析する。

音声解析に失敗して文字起こしへ戻る場合も、日本語の文字と音声の時刻を照合する。未判定発声の仮区間を外して、同じVAD発声内で語尾の探索範囲を最大1秒延長し、次の台詞・判定済み発声・動画末尾で止める。照合に成功した場合は文字の終了位置と最大0.1秒の余裕まで補正し、その後に残った未判定音だけを戻す。照合の確度が不足する場合は延長した暫定区間と警告を保持する。時刻を補正できても感情・発声分類の解析失敗は解消扱いにしない。

解析区間の境界で同じ文字起こしが複数の失敗区間に分かれた場合は、元の発言の識別番号と時刻の連続性を確認し、時刻合わせの前に一文へ戻す。文章が同じだけでは結合しないため、実際の繰り返し発言や、音声解析に成功した別イベントは保持する。

日本語CTCとの照合はWhisperが作った台詞だけに行う。Hugging Face版モデルへの入力には、特徴抽出器と同じ区間ごとの平均・分散による正規化を適用する。低い文字信頼度や文字数に対して極端に短い照合結果は採用せず、元の区間を保持して自動復旧を試し、解決できなければ無音化する。照合できた短い台詞の前後に長い無音がある場合は、その無音を合成時間から除く。CTCが文字に付けた長い無音はVADの境界で除き、単語を途中で切らず、発声の切れ目で分割する。語尾の伸ばしは近接するVAD終端まで保持する。Whisperの単語時刻も`transcript.json`に保存する。Geminiの文章は文字起こしには使わない。独立した笑い声は空の台詞と`vocalization=laugh`で保持する。

Geminiの一つの音声イベントが複数のWhisper発言を十分に覆う場合は、各発言へ感情・話し方を適用する。確認が必要になった発言は理由を保存して無音化し、画面には自動無音化した件数を表示する。

1秒以下の短い発言では、音声イベントとの実際の重なりが0.2秒以上ある場合に限り、50%の重なり基準に0.05秒の許容幅を設ける。「というか」のような短い発言が僅かな時刻差で解析失敗扱いになるのを防ぐ。重ならない発言や重なりが不足する発言、解析自体が失敗したイベントの警告は解除しない。

解析キャッシュは`events-v6-*.json`を使用し、音声内容・モデル・プロンプトから識別する。形式が正しい回答は部分的な未判定区間があっても保存し、再利用時にも区間ごとの検証を行う。VADのない再解析区間はモデルへ送らず、同一の非言語発声が機械的な等間隔で大量反復する回答は無効とする。VADと一致しない非言語イベントは発声種類を確定せず、音声が検出された区間だけを未判定として残す。旧`analysis-*.json`は新しい解析には使わない。既に解析済みのジョブは自動で書き換えないため、新方式を試す場合は動画を再アップロードする。

Geminiの音声入力は[公式の音声理解ドキュメント](https://ai.google.dev/gemini-api/docs/generate-content/audio)に沿って、同一のuserメッセージにWAVと指示を格納する。Gemini 2.5 Flashでは思考を無効にした直接の音声判定を使用する。時刻や発声種類の正しさはモデル回答だけで保証せず、VAD・文字照合・再試行で検証する。

2026-09-30に保存済みの「こんにちは＋笑い声」動画で、台詞1.916〜2.916秒と笑い声3.612〜4.580秒の2区間への分離を確認した。通常の約12秒の台詞動画でも4文を抽出できた。これは解析工程の検証であり、今回の変更後の音声生成・最終MP4の音質検証は含まない。

### その他

- アバターのポーズは、生成された実況音声で2秒以上の無言が続いた後、次の発声が始まった時に別のポーズへ切り替える（10fps、0.1秒単位）。発言中・無言中・冒頭の最初の発声では維持する。配置プレビューは音声生成前のためポーズを固定する。変更の適用にはMovieワーカーを再起動して動画を書き出し直す。無言の基準は `movie_worker/media.py` の `POSE_SILENCE_SECONDS` で調整できる。
- 同じ発声開始時に、中心位置を保ったままアバターを100% → 110% → 100%へ拡大・縮小する。0.1秒で拡大し、0.2秒で元に戻す（アニメーション計算は30fps、完成映像のフレームレートに合わせて表示）。ポーズが1種類の場合も動作する。スケール動作は完成MP4に焼き込み、音声生成前の配置プレビューでは行わない。長さと最大倍率は `AVATAR_SCALE_SECONDS`、`AVATAR_SCALE_PEAK` で調整できる。
- 一人の日本語実況を対象とし、混合済み音声の分離はしない。
- 笑い・悲鳴・ため息などの非言語発声は種類を判定してIrodoriで再生成し、生成結果にも同じ発声が自然に含まれるかGeminiで検査する。未整列文字、解析不一致、生成検査の失敗は該当発言を自動無音化する。出力はIrodori生成音声または無音だけを許可し、元実況音声へ切り替える機能は提供しない。
- Movie処理中の代表音声プレビューと試聴承認は行わない。保存する声モデルの品質確認はVoice側で完了している前提とする。
- ベースモデル情報のない既存の声モデルは、現サーバー設定を固定して使用する。過去の学習チェックポイントを自動で証明することはできない。
- 現バージョンの時刻編集はユーザーが指定した開始・終了を使用する。内容の修正後も映像上の配置区間を維持する。
- 非言語発声にはIrodoriの絵文字制御とcaptionを併用する。2026-09-24に使用中のAnimeモデルと保存済み声モデルで、`🤭🤭` による純粋な笑い声を生成し、Geminiが自然な笑い声と判定することを確認した。ほかの種類も生成後の検査を通過した結果だけ採用する。
- 完成映像はstream copyを使用する。H.264以外は画面試聴用に別のH.264プレビューを作る。ダウンロードするMP4の映像は元のコーデックを維持する。
- GPU推論中の中止は、その1回が終了してから確定する。音声サーバーのGPU排他を迂回しない。
- 60分の実実況での通し処理時間と品質は、対象動画での評価が必要。処理時間を固定値で保証しない。

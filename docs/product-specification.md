# Chibichara Studio プロダクト仕様書

最終更新：2026-10-13

## 1. この文書の位置付け

Avatar・Voice・Movieを含むプロダクト全体の仕様をまとめる。現行ソースコードと、開発時に決定した製品方針を対象とする。

- **実装済み**：現在のコードが提供する動作。
- **製品方針**：開発上の必須条件。実装が完全に満たしていることとは区別する。
- **未実装・要検証**：将来対応または検証が必要な事項。

過去の会話や設計案と異なる場合、現在の動作は本書の「実装済み」を参照する。既存の [Movie詳細要件](movie-requirements.md) には目標仕様も含まれる。[Movie導入手順](movie-setup.md) は環境構築を扱う。

## 2. 製品の目的と必須方針

ユーザーが自分の声や見た目を公開せず、独自のキャラクターと声でコンテンツを制作できるようにする。

| 項目 | 方針 |
| --- | --- |
| キャラクター | 属性や文章から独自の外見を作成する |
| 声 | 合成したキャラクター音声から再利用可能な声モデルを作る |
| 実況変換 | 発言内容、タイミング、感情、笑いなどをキャラクターの声で再生成する |
| 原声の扱い | 元実況音声を完成動画へ戻す機能・フォールバックは禁止する |
| 生成失敗 | 元声を残すより無音を優先する |
| 長時間動画のUX | 数百の発言を一つずつ必須確認させない全自動処理を目指す |
| Google送信の説明 | 利用規約・プライバシー情報で扱い、Movieページの個別確認チェックは設けない |

**現行の制約：** Movieは入力映像の上にAvatarを重ねるが、顔の検出・隠蔽・自動置換は行わない。ゲーム音トラックに混入したマイク音声の分離も行わない。したがって、必要なら顔を映像外で隠し、本人の声が混ざっていないゲーム音トラックを用意する。個別同意UIの削除は実装済みだが、それ自体は利用規約の公開・同意管理の完成を意味しない。

## 3. 画面構成

| URL | 機能 |
| --- | --- |
| `/` | `/avatar` へ移動 |
| `/avatar` | キャラクター画像、ポーズ付きアバター、表情差分の生成 |
| `/voice` | 声のデザイン、学習用音声の生成、声モデルの学習・保存 |
| `/movie` | MP4アップロード、実況解析、発言の再生成、動画書き出し |

Voiceで保存した最新の声と、Avatarで保存した最新のポーズ画像をMovieで利用する。声とAvatar画像はMovieジョブへ固定し、後から各スタジオの保存内容を変更しても進行中の出力は変わらない。

## 4. Avatarの仕様

### 4.1 キャラクター作成

実装済み：

- 属性選択またはキャラクター全体の自由記述から画像を生成する。
- 属性には性別、髪型、髪色、目の形、目の色、服装を含む。個別属性の自由記述にも対応する。
- 全体の自由記述は画面上800文字まで。
- 基本画像は1人のちびキャラ、全身、白背景、少し左向き、目を開け口を閉じた基準デザインを指示する。
- 基本画像を参照して、ポーズを指定したアバターを作成する。
- アバター作成には先にキャラクター画像が必要。

### 4.2 表情差分とプレビュー

「アバター生成」は候補を選択済み、または文章指定を有効にしたポーズのうち、未生成・生成時から指定を変更したものだけを対象に、ポーズ1→2→3の番号順で連続生成する。生成時の指定文とプロバイダーを各ポーズの画像と一緒に保存して比較し、指定を元に戻した場合も再生成しない。表示中のポーズ欄には依存しない。各ポーズは同じキャラクター画像を参照して4枚を生成し、画像生成APIは1枚ずつ順番に呼び出す。1ポーズだけの変更なら4枚、2ポーズの変更なら8枚、初回に3ポーズを選択した場合は12枚となる。未選択・変更のないポーズの保存済み画像は保持する。

生成開始時の選択内容を今回の対象とし、生成中の編集は次回から反映する。対象すべての入力を生成開始前に検証し、文章指定が空ならそのポーズ欄を表示して入力を求める。全ポーズが未選択の場合は選択を求める。ポーズ1も選択解除した場合はスキップする（初期状態は通常立ちが選択済み）。進捗には現在のポーズと全体の生成枚数を表示する。

各ポーズの4枚が完成した時点で、そのポーズを追加または上書きしてIndexedDBへ保存し、次のポーズに進む。途中で生成に失敗した場合は以降の生成を停止し、今回完成したポーズと、未完成・未着手のポーズの以前の画像を保持する。再度生成すると、未完成・未着手の変更分だけを生成する。生成操作は「アバター生成」に一本化し、ボタン上部に生成対象と枚数を表示する。各ポーズ欄のボタンに生成状態のラベルは表示しない。変更がない場合はAPIを呼ばない。キャラクターを新しく生成した場合は全ポーズをクリアする。

キャラクターとアバターの生成状態・画像・進捗・エラー・編集設定は、ページから独立したブラウザ内の共有セッションに保持する。同じタブ内でVoiceやMovieへ移動しても生成を継続し、Avatarへ戻ると現在の進捗と完成画像を自動表示する。進行中は再度の生成・削除を無効にし、生成中の設定変更は次回へ反映する。ページへ戻る際に古いIndexedDBの画像で共有状態を上書きしない。ページの再読み込みやタブを閉じた場合は共有セッションを失い、次回はIndexedDBに保存済みの完成画像と編集設定を復元する。

指定文の比較情報を持たない旧保存データは、復元時の保存済み編集設定を基準に移行し、画像を生成し直さずに保持する。移行後は、この基準から変更したポーズだけを生成対象とする。

開発UIでは、各ポーズの設定欄にある「削除」から、そのポーズの画像4枚だけをIndexedDBとプレビューから削除できる。他のポーズ、キャラクター画像、ポーズの指定内容は保持し、削除後は「アバター生成」で同じ指定から生成し直せる。最後のポーズを削除した場合はアバターのプレビューを空にする。生成中・削除中は削除を無効にし、保存に失敗した場合は画像を残してエラーを表示する。本番UIと本番UIプレビューには削除操作を表示しない。

ポーズごとに次の4枚を生成する（保存できるのは最大3ポーズ・12枚）。

| 差分 | 目 | 口 |
| --- | --- | --- |
| 1 | 開く | 閉じる |
| 2 | 開く | 開く |
| 3 | 閉じる | 閉じる |
| 4 | 閉じる | 開く |

プレビューではタイマーで口の開閉と瞬きを切り替える。複数のポーズを生成した場合は、4秒ごとに現在とは異なるポーズをランダムに選ぶ。開発用のフレーム確認ではポーズと表情を選んで停止できる。現行の口パクは音声解析に同期していない。生成したキャラクター画像とすべてのポーズ差分は、ローカルのToonOutで背景を除去した透過PNGとして表示・保存する。

キャラクター画像と生成済みポーズの4枚セットは、同一ブラウザ・同一オリジンのIndexedDB（`chibichara-avatar`）へ自動保存する。属性・文章・ポーズ選択などの編集設定も保存し、再読み込み時に画像生成APIを呼ばずに復元する。アニメーションのフレーム切替では書き込まない。生成成功時に画像セットを一括更新し、キャラクターの再生成成功時は保存済みの古いポーズをクリアする。生成失敗や保存失敗では直前の保存済み画像を保持し、保存・復元に失敗した場合は画面に通知する。アカウント同期やサーバー上の画像ライブラリは提供していない。

### 4.3 画像生成API

- `POST /api/generate-image`。
- 本番環境のキャラクター・アバター生成はOpenAI `gpt-image-2.5-sunburst` のみを使用し、qualityは `high`、サイズは `1024x1024`。サーバー側で固定し、リクエストのプロバイダー指定や `OPENAI_IMAGE_MODEL` による本番モデルの変更を受け付けない。OpenAIで失敗してもVertex AIへフォールバックしない。実行環境に `OPENAI_API_KEY` が必要。
- 開発環境にはVertex AIとOpenAIの選択がある。「本番UIを確認」ではOpenAIを使用する。開発用モデルの既定値はVertex側 `gemini-3.1-flash-image`、OpenAI側 `gpt-image-2.5-sunburst` で、開発環境では環境変数で変更できる。提供事業者の将来の利用可否を保証するものではない。
- Vertex側は1:1、512サイズの画像を要求する。
- APIのプロンプトは2,000文字まで。参照画像はPNG/JPEG/WebPのdata URL、1枚あたり5 MiBまで。補助参照画像には主参照画像が必要。
- プロンプトと参照画像を選択された外部サービスへ送る。認証情報はブラウザへ渡さない。
- 外部の画像生成を呼ぶ前にローカルToonOut workerの稼働を確認する。生成結果はToonOut（`joelseytre/toonout`）とBiRefNetでマスクを推論し、元の解像度へ戻したアルファチャンネル付きPNGとして返す。ToonOutが停止中または処理に失敗した場合は透過していない画像へフォールバックせず、503エラーにする。
- 画像間の一貫性を保つため、非透過の生成元画像は次のimage-to-image編集にだけ内部参照として使用する。UIへ表示する画像とポーズ差分としてIndexedDBへ保存する画像は透過PNGとする。キャラクターの非透過元画像は、再読み込み後もポーズを生成できるよう同じIndexedDBセッション内に内部参照として保持する。

## 5. Voiceの仕様

### 5.1 声のデザイン

実装済み：

- 性別印象、年齢印象、声の高さ、声質、声の明暗、キャラクター性を選択する。
- 各属性は自由記述へ切り替え可能。個別自由記述は120文字、全体の声説明は1,000文字まで。
- 固定の5文章を学習サンプルとして順次生成する。
- 最初の音声は指定した声説明から生成し、後続音声は最初のWAVを一時参照音声として利用して声を揃える。
- 新規生成では新しい声のサンプル群を作る。途中失敗の再試行では、説明が変更されていなければ同じ参照を使って続行する。
- 生成したサンプルを試聴し、Speaker Inversionで声モデルを学習する。

本人の実声を学習の必須入力にする構成ではない。合成サンプルからキャラクター声を作る。

### 5.2 学習・保存

- 学習処理はIrodori-TTSサーバーで実行する。
- 起動スクリプトの既定学習ステップ数は3,000。音声生成の40ステップとは別の値。
- 学習中はGPU競合を避けるため音声合成と調整する。
- ブラウザを閉じてもサーバー上の学習は継続する。
- ジョブIDをlocalStorageへ保存し、画面を開き直した際に進捗を復元する。
- 画面が学習完了を検知すると、学習結果をその所有者の最新の声として保存・置換する。
- 「ボイスモデルを削除」は、その保存モデルを音声サーバーから削除してから、ブラウザ内のモデル情報と音声サンプルをクリアする。削除中は生成・学習・削除操作を無効にし、サーバーへの削除要求が失敗した場合はモデル情報とサンプルを残して再試行できる。既にサーバーから削除済みの場合もローカルのクリアは行う。
- `.speaker.safetensors` のダウンロードにも対応する。
- Movieは保存済みの最新モデルをジョブ開始時に固定する。後でVoiceのモデルが更新されても、処理中のMovieが別の声へ切り替わらないようにする。

### 5.3 音声生成API

`/api/generate-speech` がIrodoriの `/v1/audio/speech` を中継する。WAVを返し、声説明・参照資産・速度を受け付ける。Voice側APIの速度範囲は0.25〜4.0。Movieの時間合わせは独立した処理であり、この速度範囲を適用しない。

## 6. Movieの入力と操作

### 6.1 入力条件

| 項目 | 実装済みの制限 |
| --- | --- |
| コンテナ | MP4 |
| 長さ | 0秒より長く、60分以下。60分ちょうどは受け付ける |
| ファイル容量 | 既定20 GiB。`MOVIE_MAX_BYTES` で変更可能 |
| 映像 | 映像ストリームが必要。対応検査対象はH.264、HEVC、AV1、MPEG-4、VP9 |
| 音声 | 独立した音声トラックが2本以上必要 |
| 音声割り当て | 第1音声をゲーム音、第2音声を実況音として固定 |
| 想定言語・人数 | 日本語、一人の実況 |
| 保存件数 | 所有者あたり期限切れを除き最大5ジョブ |
| チャンク | 8 MiB単位のアップロード |

ステレオの左右チャンネルは2トラックとして扱わない。ゲーム音に本人の声が混ざっている場合は、現行の変換処理だけではその声を除去できない。

### 6.2 現在の操作フロー

Movieの画面はAvatar・Voiceと同じロゴ・タイトルのヘッダーと、動画ボックス1つで構成する。アップロードはボックスへのドラッグ＆ドロップまたはファイル選択で開始し、処理状況・完成動画の再生とMP4ダウンロードを同じボックス内に表示する。最近の動画、音量・辞書設定、実況WAVのダウンロード、診断ログはボックス右上のメニューから内部オーバーレイで開く。共通のスタジオナビゲーションは維持する。

動画を受け付けるには、Voiceに保存済みのボイスモデルと、Avatarに保存済みの4表情フレームが揃ったポーズが1つ以上必要。ボイスモデルは、現在のブラウザのVoiceセッションに保存済みモデルIDがあり、音声サーバーにも保存モデルがある場合のみ利用可能と判定する。過去の削除漏れでサーバーにモデルだけが残っていても動画を受け付けない。どちらかがない場合は初期画面のドロップ案内を作成・保存を促す文章とVoice／Avatarへのリンクに切り替え、ファイル選択・ドラッグ＆ドロップ・別動画の選択・アップロード再開を受け付けない。保存状態の確認中も動画は受け付けない。

配色・角丸・文字の太さ・ボタンの影はAvatar・Voiceに合わせる。白とクリーム色のパネル、シアンの操作アクセント、赤い実行ボタン、黄色のダウンロードボタンを使用し、設定・履歴も同じライトテーマに統一する。動画の再生領域のみ黒背景とする。

1. Voiceで声モデルを、Avatarでポーズ付きアバターを作成・保存する。
2. MovieでMP4を選ぶ。Google送信の個別チェックはない。
3. アップロード完了後に形式・時間・トラックを検査する。
4. 第1音声をゲーム音、第2音声を実況音として固定する。
5. アップロードした元動画を動画ボックス内で再生し、内容と音声を確認する。この確認ステップでは再生・一時停止・シーク・音量操作ができ、まだ解析や変換は開始しない。
6. 必要に応じてゲーム用語等の辞書を入力する。最大2,000文字。
7. 動画右上の「変換を開始」を実行する。
8. 解析完了後、そのまま全体変換とMP4書き出しを実行する。解析や生成で確認が必要になった発言は自動的に無音化する。
9. 生成・検査・ミックス完了後、MP4を試聴・取得する。

確認画面には保存済みアバターを自動表示する。右上の配置ボタンからドラッグ移動、大きさ、回転、左右反転を調整できる。中心座標は動画幅・高さ、大きさは動画高さに対する比率で保存し、中心を動画外へ置くことも許可する。出力キャンバス外の部分は自然に切り取られる。変換開始時にPNGと配置をジョブへ複製する。確認中の既存ジョブにも、変換開始には保存済みまたはジョブへ複製済みのアバターが必要。

完成動画では生成済み実況WAVを10fpsで解析し、発声中だけ口開きフレームを使用する。無音では口を閉じ、まばたきと4〜8秒間隔のポーズ変更を加える。乱数seedをジョブへ保存するため再書き出しでも同じ動きになる。プレビューは配置確認用の簡易アニメーションであり、最終的な口の動きは生成音声から確定する。

**発言単位の確認と代表プレビューは不要。** 解析後は全体変換へ自動で進む。解析中は時刻補正後の再照合と発言単位の再解析で自動復旧を試み、感情だけが不明なら自然な会話調で続行する。台詞・時刻・未判定発声などを解決できない発言や、音声生成に失敗した発言は理由を保存して無音化し、他の発言と動画処理を続行する。

### 6.3 発言の自動処理

- Movie画面には発言ごとの編集・確認操作を表示しない。
- 正常な発言は声を変換し、確認が必要な発言は無音にする。元実況音声を完成動画へ採用する選択肢はない。
- 自動無音化した件数を処理結果に表示し、理由は各発言の `fallback_reason` と `analysis_resolution` に保存する。
- 既存の発言編集APIは保存済みジョブとの互換性のため残すが、編集後も `needs_review` には遷移しない。

## 7. Movieの音声解析

### 7.1 ローカル処理

1. FFmpegでゲーム音と実況音を抽出する。
2. 実況をモノラル化し、解析用に16kHzへ変換する。
3. Silero VADで発声候補を検出する。
4. faster-whisperで日本語を文字起こしする。既定モデルは `large-v3`、CPU・int8で動かす。
5. WhisperXの日本語アライメントで文字と時刻を対応させる。
6. 句読点・無音などを利用して発言区間をまとめる。
7. 文字起こしが説明しきれなかった発声も候補として残す。

語尾を「不明な発言」と誤分割しないよう、同じVAD発声内ではアライメントの探索終了を最大1秒延長する。次の文字起こし区間や動画末尾を越えない。

Whisperは台詞本文、アライメントはその本文の時刻、Geminiは感情・話し方・非言語発声の解析を担当する。Geminiの台詞文字列は採用せず、Whisperとの文字列比較も行わない。アライメント成功だけでは文章の正しさを保証できない。

### 7.2 Geminiへ渡す内容

- 音声を約30秒の窓に分け、可能な場合は発声の間の無音を境界に使う。境界がWhisper発言の内部に入る場合は、発言後の安全な無音まで窓を延長する。
- 長い前後の無音を除く場合、約150msの余白を残す。
- 16kHz・モノラルWAVをVertex AIのリクエストへ直接埋め込む。
- 通常解析では音声の長さと解析指示を送信し、発声イベントの相対時刻と音響分類を受け取る。通常台詞の本文は要求せず、`suggested_text`は空に固定する。発言単位の再解析では補正済みの原音、固定した発言ID、Whisperの台詞を送信し、時刻の推定や新しい文字起こしを求めない。
- 既定モデルは `gemini-2.5-flash`、temperatureは0。JSONスキーマで返却形式を指定する。
- 元の性別・年齢・声質の記述、セリフの創作・要約をしないよう指示する。
- 音声窓ごとの解析結果を保存し、再開時に利用する。
- 504 `DEADLINE_EXCEEDED`では同一音声を再送せず、安全な別境界または異なる前後文脈で再試行する。解決しない場合も該当窓の発言だけを無音化し、後続窓を続行する。

### 7.3 発言ごとの結果

| フィールド | 値・意味 |
| --- | --- |
| `emotion` | neutral / joy / surprise / anger / fear / sadness / confusion / relief / unknown |
| `style` | normal / whisper / shout / laugh / cry / breathy / rushed |
| `strength` | 感情の強さ、0〜1。正解確率ではない |
| `pace` | slow / normal / fast |
| `emphasis` | 強調する原文の部分文字列 |
| `suggested_text` | 聞こえた全文の修正候補 |
| `nonverbal` | 言葉を伴わない発声か |
| `vocalization` | none / laugh / scream / sigh / cry / gasp / breath / cough / other |
| `uncertainty` | 聞き取り・判定の不確実性の説明 |

発言IDの欠落・重複や不正な分類は解析エラーにする。通常発言の本文はWhisperの文字起こしを使用し、Geminiの台詞候補との比較や自動上書きは行わない。

### 7.4 発言単位の自動復旧

- 文字と音声の時刻補正後、未解決の台詞を保存済みの発声イベントと再照合する。双方の区間の半分以上が重なり、候補が一つで、隣の発言と競合しない場合だけ採用する。
- 時刻の確度が不足する場合は、その発言だけを前後の発言・同じVAD発声の範囲内で再アライメントする。時刻を確認できないまま解析警告を解除しない。
- 対応するイベントが見つからなければ、その発言IDと原音・台詞で再解析する。通常の切り出しと前後最大150msの余白付きの最大2回で、隣の発言を含めない。
- 原音で台詞全体を確認でき、感情・話し方だけが不明な場合はneutral/normalで続行する。台詞不明・不一致・無発声・音声を処理できない回答は発言を無音化する。
- 80ms未満で音声照合に失敗した台詞が、直前10秒以内の音声確認済み発言と4文字以上一致する場合は、Whisperの重複文字起こしとして自動的に無音化する。短い相槌や、音声で確認できる反復発言は対象にしない。
- 応答は音声・発言ID・台詞・モデル・指示のハッシュで保存する。キャンセルはそのまま伝播し、発言単位のAPI障害は理由を保存して無音化する。
- `analysis_issue`に問題の種類、`analysis_resolution`に解決方法と元の警告を記録する。復旧した発言はIDと本文を保持し、revisionを更新して生成する。
- 全体変換の続行時に旧ジョブの未解決発言が残っている場合も、その発言だけを無音化する。生成済みの発言は維持する。

## 8. Irodoriによる再生成と時間合わせ

### 8.1 声と発声指示

- 使用中のモデル構成は `phasefield-audio/Irodori-TTS-v4.1-Anime` を前提に運用している。実際の選択はIrodori側設定に依存する。
- Movieは声モデルのスナップショットとハッシュを保存し、生成前に検査する。
- モデル・CodecともFP32を要求し、生成時40ステップ、候補数1、逐次生成、テキスト自動分割なしを指定する。
- Seedはジョブ・発言ID・revision・試行番号から決める。
- 感情と話し方を日本語captionへ変換する。
- strengthが0.4未満なら控えめ、0.75以上なら感情を伝える指示を加える。3回目の試行でも控えめな指示にする。
- slow/fastと、読みの中に実在する強調箇所をcaptionへ反映する。

### 8.2 時間補正

- 発言の終了時刻−開始時刻を目標時間とする。
- Irodoriには秒数を固定せず、モデルの時間予測で発声可能な自然長を生成する。
- 生成音声の前後の無音を整理し、`生成音声時間 ÷ 目標時間` で補正倍率を求める。
- FFmpegのatempoで音程を保って速度補正する。±10%の旧制限は撤廃済み。
- 0.5〜2倍の複数段を組み合わせて大きな倍率にも対応する。
- 最後に切り詰めまたは無音補完で、48kHzのサンプル数を区間と一致させる。
- 生成音声を絶対時刻に配置し、区間間の無音を保持する。音声を単純連結しない。

**品質の限界：** 長さの一致と発音の完全保持は別の条件。生成後の再認識は行わないため、発音の確認は試聴で行う。

### 8.3 通常発言の品質検査

最初のWhisper文字起こしを台詞として使い、編集した場合は保存した読みを優先する。生成音声の再文字起こし、読みの不一致判定、それに伴う自動再生成は行わない。音声ファイルの読み込み、発声の有無、クリッピング、区間に合う長さは確認する。旧仕様の読み不一致で停止した発言は、続行時に有効な保存済み音声を再利用する。

## 9. 笑い声・非言語発声

### 9.1 生成制御

| 種類 | Irodoriへの制御 |
| --- | --- |
| 笑い | 🤭 |
| 悲鳴・叫び | 😱 |
| ため息 | 😮‍💨 |
| 泣き声・嗚咽 | 😭 |
| 息をのむ | 😮 |
| 息遣い | 🌬️ |
| 咳・咳払い | 🤧 |

読みが空なら種類ごとの絵文字入力だけで生成する。読みがある場合は読みの末尾に制御を追加する。種類別captionも併用する。Geminiが特定の非言語発声と判定した場合、文字にならない発声という保留を解除する処理がある。

### 9.2 検査と失敗時

- 生成・時間補正後のWAVをGeminiへ送り、目的の発声が含まれるか（present）、発声として自然に成立するか（natural）を判定する。
- 両方が真の結果を採用する。台詞を含む場合は通常の読み検査も行う。
- 最大3試行で不合格の場合、台詞や発声種類にかかわらず該当発言を自動無音化する。理由を `fallback_reason` に保存する。
- ある発言の生成・検査失敗を理由に、動画全体を確認待ちへ移さない。
- 元実況音声を代替出力にすることは禁止。旧 `original` 設定も新規書き出しでは無音にする。

### 9.3 検証状況と未解決事項

2026-09-24、使用中のAnimeモデルと保存済み声モデルで `🤭🤭` を実生成し、Geminiが自然な笑い声と判定した。これは1候補の機械判定であり、全種類・全話者・元の笑い方の忠実な再現を保証する検証ではない。他候補の検査ではGoogle側504も発生した。

現行実装では、発言内の笑いの正確な位置や複数の非言語種類を個別に制御していない。また、純粋な非言語発声でも読みが残っていると読み検査の対象になる。初回プレビューの選出条件は本文のある発言を優先するため、笑いだけの動画が自動プレビューまで進めない場合がある。

## 10. ミックスと出力

- 変換後の実況PCMを48kHzで作り、ゲーム音とミックスする。
- 実況PCMに書くのは生成音声または無音。元実況の波形をコピーする経路は設けない。
- 元実況の音量は生成音声の音量調整の参照に利用する。
- ゲーム音と声のゲインは0〜2、初期値は各1。
- 出力はゲーム音と生成実況をまとめたAAC音声1本を持つMP4。
- アバターなしでは映像をstream copyで維持する。アバターありでは透過PNGを配置・回転・反転し、口・目・ポーズのタイムラインに従って重ね、H.264へ再エンコードする。
- アバターなしのH.264以外では、画面試聴用の別プレビューを作る処理がある。
- 元音声との比較素材は所有者向けAPIから取得する。完成動画への原声採用とは分離している。
- 本仕様への変更は、既に作られた完成ファイルを自動的に再書き出しするものではない。

## 11. ジョブ管理とデータ保存

### 11.1 状態

| 状態 | 意味 |
| --- | --- |
| uploading | チャンク受信中 |
| queued | 実行待ち |
| validating | 入力検査 |
| ready | 解析開始待ち |
| analyzing | 文字起こし・時刻合わせ・Gemini解析 |
| synthesizing | 発言生成・品質検査 |
| preview_ready | 旧ジョブの自動変換待ち（画面表示時に変換を開始） |
| needs_review | 旧ジョブとの表示互換用。新しい処理では遷移しない |
| mixing | MP4書き出し |
| completed | 完成 |
| failed | エラー終了。条件を満たせば再開可能 |
| cancelling / cancelled | 中止待ち／中止済み |
| expired | 期限切れまたは削除済み |

SQLiteの `jobs` に所有者、状態、発言、進捗等をJSONとして保存する。既定の素材保存先は `.movie-data/<ジョブID>/`。入力MP4、抽出音声、文字起こし、Gemini解析結果・利用量、声モデルのコピー、生成WAV、完成MP4等を保持する。

### 11.2 再開・中止・期限

- アップロードの位置とチャンクハッシュを管理し、同じファイルで再開できる。
- ワーカーはジョブを1件ずつ実行する。プロセスの排他ロックを持つ。
- 起動時に中断した処理をキューへ戻す。保存済み解析や生成済み発言を利用して再開する。
- 中止は安全なチェックポイントで行う。GPU生成リクエストを途中で強制終了する方式ではない。
- 実行中のジョブの削除は拒否し、中止後に削除できる。
- 既定保持時間は最終更新から24時間。実行中状態は期限削除の対象外。
- ファイル削除後は `expired` として扱う。削除APIは即時物理消去の証明を返すものではなく、保持・削除の厳密な運用監査は別途必要。

## 12. 外部送信と所有者管理

| 処理 | 送信先 | 主な送信データ |
| --- | --- | --- |
| Avatar生成 | Vertex AIまたは選択したOpenAI経路 | プロンプト、参照画像 |
| Movie表現解析 | Vertex AI Gemini | 元実況の音声窓、文字起こし、ID・時刻、指示 |
| 非言語発声の品質検査 | Vertex AI Gemini | Irodori生成音声、検査する発声種類、指示 |
| Voice生成・学習 | 設定されたIrodoriサーバー | テキスト、声説明、合成学習サンプル、声モデル情報 |
| Movie音声生成 | 設定されたIrodoriサーバー | 読み・制御文字、caption、目標秒数、声モデル参照 |
| 元音声の文字起こし・生成音声の読み検査 | Movieサーバー内 | ローカルWhisperで処理 |

Movieの映像、MP4全体、ゲーム音トラックをGeminiへ送る処理はない。ただし、実況として選択したトラックに混ざっている音は、そのトラックの音声として送信される。

**以前の説明との差分：非言語品質検査の追加後は、Irodoriが生成した音声もGoogleへ送る。** Google側の保持・利用条件はサービス設定・契約に依存し、ローカルファイルの削除と同じものではない。

所有者はHttpOnly Cookie `chibichara-voice-owner` で区別する。SameSite=strict、本番はSecure、最大有効期間は1年。これはログインアカウントではない。Cookieが失われた場合の資産復旧や端末間同期は実装していない。

Next.jsからMovieへ所有者ヘッダーと内部トークンを付けて中継する。Irodoriにも所有者情報を渡す。素材取得は許可されたファイル名と所有者を検査し、private/no-storeおよびRange取得に対応する。声モデルの内部パスやサービス認証情報を公開APIのジョブ情報から除外する。

## 15. Movie自動処理の残作業

発言単位の確認と代表試聴をなくし、解析・生成で確認が必要な発言を自動無音化して全体変換へ進む処理は実装済み。以下は今後の改善項目。

1. Whisperを本文の正解として採用した発言単位と、Geminiの感情・非言語発声分類を実音声で評価する。
2. 自動無音化の区間と理由を完成後に一覧表示する。現在は件数表示と内部の理由保存までで、専用一覧UIはない。
3. 非言語発声だけの動画、台詞と笑いが同一区間にある動画、短い笑い・息の検出を改善・検証する。
4. 全件無音やサービス障害まで正常完成と扱わない基準、再試行の時間・費用上限を決める。
5. 40〜60分の実実況で、全文処理時間、発言再現、声の一貫性、無音化率を測定する。
6. 本番用の認証、端末間の資産管理、利用規約の公開と同意管理、運用監視・容量管理を整える。
